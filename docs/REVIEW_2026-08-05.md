# Independent review — 2026-08-05, at `da7ad63`

Three reviews ran concurrently: code, design, and adversarial testing of the suite.
**Result: aimail is NOT fit to run a fleet.** The mail half is sound; the supervision
and lifecycle half does not work. Ids `AR-NN`.

⚠ **Method note, and it is a finding about me, not the code.** The three reviewers were
launched against ONE shared working tree and mutated it under each other; one review's
suite run was contaminated by another's live mutant. That is root cause RC-3 — a shared
mutable instrument with no announcement channel — caused by how the review was
orchestrated. Two reviewers moved to private clones and re-ran. **Any future parallel
review must give each agent its own clone.**

⚠ **A verification of mine failed the same way it was checking for.** Verifying the
concurrent-send defect, I cloned the repo and ran 20 trials that reported "20/20 lost".
`bin/aimail` came out of the clone **non-executable**, so nothing had run. The number was
produced by a broken instrument, in the check meant to catch exactly that. It was caught
only because the exit codes were 126. **Assert your instrument ran before believing its
output** — see AR-17, which that accident discovered.

---

## Two roots explain most of the severe findings

**R-1 — Message identity is `(second, from, subject-slug)`, the collision check looks in
one directory out of three, and all three moves use `mv -f`.** `lib/mail.sh:129-131`
checks only the inbox; `mail_deliver:227` and `mail_ack:275` then overwrite whatever is
at the destination. ⇒ AR-01, AR-02.

**R-2 — The poller's wake predicate and the delivery predicate disagree about what counts
as a message.** `poller.sh:112` counts anything matching `*.md` via `find | wc -l`;
`mail.sh:212` skips anything that is not a regular file. Nothing reconciles them. ⇒ AR-07.

Two more that are not roots but recur: **exit codes dying in subshells** (`atomic_write`
used as a pipe sink defeats its own `die`), and **safety actions sharing a fatal path with
advisory ones** (`autopilot`'s park dies when the checkpoint refuses).

## BLOCKER — unattended operation is impossible

| Id | Defect | Evidence |
|---|---|---|
| **AR-05** | **A parked fleet can never un-park itself.** (a) the poller's throttle branch `continue`s past the ramp check; (b) `autopilot`'s ramp is gated on `now >= block_end`, but `block_end_effective` only returns future values, so it is dead code. Autopilot parks automatically every block. | poller ran to timeout with a ramp 1h overdue |
| **AR-06** | **Two unbounded wake loops, each ~5 wakes/second, each a full session turn.** `ramp_at` is never cleared after firing; and the mail wake counts `unacked/`, so a seat that re-arms without acking wakes on mail it just read. | 144/146/148 ms and 161/175 ms |

| **AR-08** | **The stop hook makes those loops inescapable.** It blocks on `RE-ARMING` — the normal post-wake state — and drains the hook JSON, discarding `stop_hook_active`, the platform's only loop-breaker, which the predecessor used. | rc=2 on every stop with `stop_hook_active: true` supplied |
| **AR-09** | **The dashboard tells you to kill a correctly parked poller.** Parked pollers skip `hb_beat`; after ~60s they read `WEDGED — ⛔ HUNG, needs a kill + restart`. **There is no PARKED state.** | verdict flipped at t+42s on a healthy parked poller |
| **AR-10** | **`autopilot` dies before the park whenever the checkpoint refuses** (`(( … )) && budget_checkpoint`, whose `refused` is `exit 3`). One missing registry row ⇒ the fleet blows through the cap with no handover. From cron nobody sees it. | rc=3, throttle absent |
| **AR-11** | **`budget park` with an unmeasurable block end parks with NO wake path** — `ramp_at` is written only when `$be` is non-empty. The file's own comment forbids this. | throttle written, no `ramp_at`, poller asleep |
| **AR-12** | **`hb_start` is four separate writes**, so a *starting* poller transiently reads `CRASHED`/`WEDGED` — the verdicts that provoke human intervention. | 10 healthy starts → 1 WEDGED, 1 CRASHED |

## DESIGN GAPS

| Id | Gap |
|---|---|
| **AR-19** | **No seat `kind`.** Registering the human makes `role stale` a predicate that can never clear — sitting on the gate for every account switch. Not registering them recreates the unregistered black hole. Needs `agent \| human \| service`. |
| **AR-20** | **Nothing actively supervises anything.** Five watchdog loops became zero; the README calls it "subsumed by `aimail fleet`", but a dashboard nobody calls is not a sweep. A CRASHED seat is invisible until a human looks. |
| **AR-21** | **No cold-start/bootstrap.** `resume` reads a handover but nothing tells a fresh session *which seat it is*. `BOOTSTRAP_PROMPT.md` is counted as "skipped" by migrate and written nowhere. |
| **AR-22** | **The size cap exempts the first message** — a 10 MB body prints in full, the exact context flood the cap exists to prevent. |
| **AR-23** | `set -u` crash (exit 1, leaking the install path) on a missing flag value: `aimail send --to`. Every other path refuses cleanly with exit 3. |
| **AR-24** | The deferral notice is emitted with no separator and can land inside a code fence; deferred mail can be starved forever by un-acked backlog. |

## What is CONFIRMED SOUND — do not churn

All three reviewers independently agreed on this list:

- The **registry as the address space**, incl. the prefix-truncated suggester and `retired` rather than deletion.
- **No `--body`, no `--date`, body from file/stdin.** Closes FI-06/07/25 by construction.
- **Four output states with distinct exit codes**; `where` exiting 4 on a miss.
- **`roles/` outside the mail glob** — the exclusion problem cannot recur.
- **The budget boundary model**: callout-beats-ccusage, *take the earlier*, print the anchor's age, discard an expired callout. Mutation-proof in both directions.
- **Decoupling the checkpoint from the percentage** — called the highest-value idea in the codebase.
- **The checkpoint marker** keyed on the block end and written only after a send succeeded.
- **`migrate`'s subdirectory traversal and dot-dir exclusion** (the logic; not the reconciliation).
- **Park-not-disarm** is a real integration test.
- `refuses`/`unmeasurable_test` (exit code **and** substring) — every refusal disabled was caught.
- Quoting discipline: `AIMAIL_ROOT` with spaces and unicode works end to end. 100 MB single-line body round-trips with a matching digest. 30 concurrent distinct `seat add`s: 30/30.
- **Delivery ordering by mtime, not filename.**

## Fix order

Each step must be **mutation-verified with the patch asserted applied** before it counts.

1. **AR-13** — make the harness fail loudly (assert an arm count and the selftest's exit
   code). Until this lands, nothing else that gets fixed stays fixed.
2. **AR-01 + AR-02 + R-1** — message identity. Make the id collision-proof, check all
   three directories, and never `mv -f` onto an existing path.
3. **AR-03 + AR-10 + AR-11** — never report success for a write that did not happen;
   take the safety actions off the advisory path; never park without a wake path.
4. **AR-05 + AR-06 + AR-07 + R-2** — the poller: ramp reachable while parked, clear
   `ramp_at`, wake on the inbox only, and reconcile the wake and delivery predicates.
5. **AR-08 + AR-09** — honour `stop_hook_active`; add a `PARKED` state.
6. **AR-17 + AR-18** — one-line each, and both block a first trial run.
7. **AR-14** — close the coverage gaps the mutation survivors name.

**AR-19..AR-24 and the gate/preland work come after.** Nothing should be proposed for a
cutover until 1–5 are done and the fleet has run on it unattended through at least one
full block boundary without human intervention.
